# 开发执行与体验基线

## 生效范围

ComfyNeko 是 Windows 桌面专业工具，按 `Tauri 2 + React + TypeScript + Rust` 实现。本文把已选定的软件开发、桌面工程与 Kuroii UI/UX Skill 规范落实为本项目的可执行门槛。

## 开发流程

1. 每项功能先在 `feat/<scope>` 隔离工作树开发；`main` 只接收通过该里程碑验证的版本。
2. 先写会因目标行为缺失而失败的最窄测试，再实现最小代码；记录失败与通过的测试证据。
3. 每一个可验证子里程碑都更新开发日志、路线图状态与 README 当前阶段，再提交并推送到对应分支。
4. 完成里程碑后，在路线图保留原文并用 `~~删除线~~` 标记完成；合并前向用户报告改动、验证、未验证项和下一步。

## Desktop UI 强制基线

- 主题：Light、Dark、Follow System，实时切换、持久化；颜色、阴影、圆角与浮层全部使用 Token。
- 国际化：首发 `zh-CN`、`en-US`，预留 `ja-JP`、`ko-KR`；禁止组件硬编码文案，缺失翻译回退 `en-US`。
- 外壳：可折叠侧栏、统一图标和 Tooltip、顶部 sticky 说明栏、设置面板与右上角功能图标区；所有纯图标操作都有 `aria-label` 与键盘可达的 Tooltip。
- 交互：组件必须覆盖默认、悬停、聚焦、激活、选中、禁用、加载、成功、警告、错误、空和只读状态；错误须可定位且可恢复。
- 桌面适配：检查 240px、320px、420px 与 1366px 宽度，不允许横向溢出；管理列表遵循 Windows 单选、Ctrl 多选、Shift 范围选择和右键批量操作模型。
- 可访问性：键盘支持 Tab、Shift+Tab、Enter、Space、Esc 与必要方向键；Focus Ring 清晰，颜色不是唯一状态信息；支持减少动效/透明度的系统偏好。

## 验收与质量门槛

- 每个 UI 任务须检查亮色、暗色、跟随系统、中文、英文、空/加载/错误状态与键盘路径。
- UI 自检评分低于 85/100 不得标为完成；必须列出待修复项。
- 环境绑定始终只读：不改动已绑定 ComfyUI、Python、模型目录或配置文件。

## 适用 Skill

- `full-cycle-software-engineer`：阶段路线、架构和质量门禁。
- `software-project-developer`：Windows/Tauri 工程、依赖、测试、打包与 GitHub 同步。
- `software-ui-ux-design-director`：信息架构、组件状态、桌面体验和视觉验收。
- `kuroii-uiux-product-standard`：主题、i18n、侧栏、Tooltip、响应式与可访问性基线。
