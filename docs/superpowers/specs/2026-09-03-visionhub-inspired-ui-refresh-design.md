# ComfyNeko VisionHub 风格 UI 第一轮改版设计

## 目标

在不改变环境绑定业务逻辑、安全边界和技术栈的前提下，重建 ComfyNeko 当前桌面前端的视觉层级、信息密度与交互动效，使其从“基础表单原型”升级为可长期迭代的专业 Windows 桌面工具界面。

本轮参考 Kuroii VisionHub 的桌面产品语言，但不逐像素复制，也不照搬其图像创作业务。ComfyNeko 继续使用自己的品牌图标、紫蓝强调色和环境管理语义。

## 设计读法

- 产品类型：Windows 本地优先的专业 ComfyUI 管理工具。
- 目标用户：同时维护一套或多套 ComfyUI、模型目录和生成资产的创作者。
- 视觉语言：紧凑、清晰、轻盈、低打扰；像成熟桌面控制台，不像通用网页表单。
- 设计基础：Kuroii 自有桌面产品系统，借鉴 VisionHub 的固定侧栏、控制条、分层面板和状态胶囊。
- 三项拨盘：
  - 设计变化度：6/10。
  - 动效强度：4/10。
  - 信息密度：7/10。

## 本轮范围

### 包含

1. 重构应用外壳、侧栏、页面控制条和环境绑定工作区布局。
2. 重构亮色与暗色 Token，包括背景、面板、描边、阴影、强调色和状态色。
3. 将四步向导改为桌面工作区结构，并为诊断信息建立独立视觉区域。
4. 增加克制、可关闭的页面进入、步骤切换、按钮、卡片和状态反馈动效。
5. 保持中文与英文、侧栏展开与收起、240/320/420/1366px 响应式能力。
6. 保留现有环境探测、保存、SQLite、Tauri IPC 和测试行为。

### 不包含

1. 不新增资产库、工作流、Run 或扫描功能。
2. 不制作新的插画、素材缩略图或虚构业务数据。
3. 不重写 React/Tauri 架构，不引入重型 UI 组件库。
4. 不在本轮完成所有未来页面；只建立可以继续复用的外壳和组件语言。
5. 不使用装饰性 `linear-gradient` 或 `radial-gradient` 作为按钮和卡片视觉。

## 信息架构

### 应用框架

应用采用固定视口桌面壳层：

```text
┌──────────────┬──────────────────────────────────────────┐
│ 品牌与导航    │ 页面控制条：标题 / 状态 / 关键上下文       │
│              ├──────────────────────────┬───────────────┤
│ 当前功能入口  │ 环境绑定主工作区           │ 状态与诊断侧栏  │
│              │ 四步表单 / 摘要 / 操作      │ 安全 / API / 问题│
│              ├──────────────────────────┴───────────────┤
│ 主题与收起    │ 页面辅助说明或快捷信息条                    │
└──────────────┴──────────────────────────────────────────┘
```

- 左侧栏固定在视口内，主内容独立滚动。
- 展开侧栏宽度约 `184–204px`，收起宽度约 `64px`。
- 内容区使用浅灰蓝背景，面板使用白色或带色相的深色表面。
- 页面主体最大宽度约 `1180–1240px`，不把表单无限拉宽。

### 侧栏

- 顶部显示 ComfyNeko 图标、名称与短定位。
- 当前只展示已有真实入口：环境；首页可保留为工作区入口，但不得伪造不可用功能。
- 导航项采用图标、文字、选中底色和细描边，不使用大面积实色块。
- 底部保留主题切换、语言入口和侧栏收起按钮。
- 收起后只显示图标，所有操作继续提供 Hover 与 Focus Tooltip。

### 页面控制条

- 采用 VisionHub 式横向控制条卡片。
- 左侧：英文 eyebrow `ENVIRONMENT CONTROL`、中文主标题和一句短说明。
- 中间：只读模式、本地优先、API 可选等真实状态胶囊。
- 右侧只放两个真实定位操作：“开始配置”聚焦当前步骤的首个输入项，“查看诊断”滚动并聚焦右侧诊断栏；不放无功能占位按钮。
- 控制条在主内容滚动时保持 sticky，但高度保持克制。

### 环境绑定工作区

桌面宽度下采用主次双列：

- 左侧主面板约占 `2fr`：
  - 顶部显示阶段说明与四步进度。
  - 中部显示当前表单。
  - 底部显示上一步、下一步、检查或保存操作。
- 右侧诊断栏约占 `0.85fr`：
  - 环境完整度摘要。
  - 只读安全说明。
  - 当前阻塞、警告或成功诊断。
  - API 与 Python 状态只展示真实探测结果。
- 当前步骤切换时只替换主面板内容，外部骨架不跳动。
- 420px 以下改为单列；诊断栏移动到表单下方。

## 视觉系统

### 颜色

- 主强调色保留 ComfyNeko 紫蓝方向，调整为更清爽的蓝紫：
  - Light accent 建议 `#6574E8`。
  - Dark accent 建议 `#AAB4FF`。
- 背景使用略带蓝色的中性灰，不使用纯灰或纯黑。
- 卡片通过描边、背景层级和轻阴影区分，不依赖强投影。
- 状态色保持语义稳定：
  - 成功：青绿色。
  - 警告：琥珀色。
  - 阻塞：珊瑚红。
  - 信息：蓝紫色。
- 所有颜色进入 CSS Token，组件内不新增硬编码业务色。

### 字体与层级

- 使用 Windows 原生 `Segoe UI Variable`，优先保证桌面一致性和中英文可读性。
- 主标题约 `24–28px`，面板标题约 `18–20px`，正文 `13–14px`。
- Eyebrow 使用大写、字间距和弱文本色，只用于建立层级。
- 英文长词、Windows 路径和诊断证据必须具备 `min-width: 0` 与断词策略。

### 圆角与阴影

- 外层控制条和主面板：`18–22px`。
- 表单、状态卡、按钮：`10–14px`。
- 胶囊：`999px`，仅用于状态和短标签。
- 阴影采用低透明蓝灰色；暗色模式以描边和表面层级为主。
- 避免每个元素都成为独立大圆角卡片。

### 按钮

- 主操作使用纯色或浅色强调底，不使用渐变。
- 次操作使用白色/深色表面加描边。
- 危险或阻塞状态不把整个按钮染红，只在确有危险动作时使用危险样式。
- 覆盖默认、Hover、Focus、Active、Disabled、Loading 状态。

## 动效规范

- 页面外壳首次出现：`220–280ms` 淡入并上移 `4–8px`。
- 当前步骤内容切换：`180–220ms` 淡入与轻微横向位移。
- 卡片 Hover：上移不超过 `2px`，阴影和描边轻微增强。
- 按钮 Hover：上移 `1px`；Active 回到原位，形成明确按压反馈。
- 状态胶囊与诊断项：颜色和背景在 `160–200ms` 内过渡。
- 侧栏展开/收起：宽度和内容透明度在 `200–240ms` 内同步变化。
- Loading 图标允许旋转或脉冲，但不引入持续装饰动画。
- `prefers-reduced-motion: reduce` 下关闭位移、缩放和循环动效，仅保留即时状态变化。

## 组件调整

### `AppShell`

- 固定 `100dvh`，侧栏与主内容分别管理滚动。
- 将品牌区、导航区和底部控制区明确分层。
- 导航项与底部按钮统一尺寸、图标线宽、Hover 与选中态。
- 主题和语言在展开态可直接操作，在收起态通过图标按钮或小型浮层访问。

### `EnvironmentWizard`

- 保留现有状态管理和 API 接口。
- 拆分视觉结构为：
  - `EnvironmentWorkspace`
  - `EnvironmentStepRail`
  - `EnvironmentFormPanel`
  - `EnvironmentStatusRail`
  - `EnvironmentActionBar`
- 现有四个步骤、校验和保存行为不改变。
- 输入区使用桌面表单分组；路径输入应支持长文本，不截断真实值。
- 当前步骤、已完成步骤和未开始步骤具备不同状态，不只依赖颜色。

### `DiagnosticList`

- 按成功、提示、警告、阻塞建立图标与层级。
- 诊断代码作为弱化辅助信息，用户消息作为主要信息。
- 没有诊断时显示清晰空状态，不显示空白卡片。

## 响应式

- `> 800px`：固定展开或可折叠侧栏，主工作区双列。
- `520–800px`：侧栏收起，主工作区仍可双列或窄诊断栏。
- `360–520px`：单列工作区，步骤轨道两列。
- `280–360px`：单列，步骤轨道两列，操作按钮允许纵向排列。
- `< 280px`：步骤轨道单列，标题允许安全断词，所有按钮铺满可用宽度。
- 240/320/420/1366px 必须满足 `scrollWidth === clientWidth`。

## 无障碍

- 保留语义标题、`aria-current`、`aria-label`、状态区域和错误区域。
- 所有纯图标按钮必须具备 Tooltip，且 Hover 与 Focus 都能触发。
- Focus Ring 不被阴影、圆角或 overflow 裁切。
- 状态不能只靠颜色区分，必须同时有图标和文字。
- Tab 顺序遵循页面视觉顺序；Enter/Space 可触发按钮。

  4. Loading 状态阻止重复提交。

## 后续迭代方向

第一轮完成后再逐步优化：

1. 设置面板与主题色配置。
2. Tooltip 延迟、边缘翻转和快捷键展示。
3. Windows DPI、High Contrast 与 Reduce Transparency。
4. 环境列表、扫描任务、资产库等新页面复用同一工作区系统。
5. 根据真实使用截图继续微调字号、间距、卡片密度和动效节奏。
