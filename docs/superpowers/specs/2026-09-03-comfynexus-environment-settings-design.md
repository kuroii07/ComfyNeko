# ComfyNeko ComfyNexus 启发式环境设置设计

## 目标

把现有“环境绑定表单”升级为 ComfyNeko 的长期环境控制中心。布局与交互借鉴 ComfyNexus 已展示的环境设置模式：固定标题栏、居中页签、左文案右配置卡的宽阔双栏区块、分组的高级运行时参数与配置集。但实现、文案、品牌和素材全部独立完成，不复制其代码、资源或产品标识。

本阶段优先完成高保真前端、内存草案与字段校验；不改变真实 ComfyUI、Python、模型、路径映射、启动脚本或系统环境变量。

## 设计读法

- 页面类型：Windows 本地专业工具的环境控制台，不是首次启动向导。
- 用户：拥有一套或多套 ComfyUI 安装、需要理解路径和运行时状态的创作者。
- 视觉语言：紧凑、安静、工程化；以宽阔的分区和清晰的配置层级取代密集小卡片。
- 设计基础：ComfyNeko 现有 Token、Lucide 图标和桌面侧栏，不混入第三方设计系统。
- 三项拨盘：设计变化度 4/10，动效强度 3/10，信息密度 7/10。

## ComfyNexus 源码审查结论（2026-09-03）

已只读审查公开仓库 `Allen-xxa/ComfyNexus` 的提交 `a85a8288c2610b0eaadbe1cfd2afd2d0c893be8a`。仓库根目录声明 Apache-2.0；尽管许可证允许在满足署名等条件下复用，ComfyNeko 本轮仍采取独立实现，不复制其代码、类名、Tailwind 类串、组件结构、产品文字、图标或视觉素材。

可借鉴且将独立重做的设计模式：

1. `EnvManagePage` 的页首采用“标题 + 当前激活状态 + 居中四页签 + 右侧保存”这一高效的专业设置结构。
2. `GeneralTab`、`AccelerationTab`、`ModelPathsTab`、`AdvancedEnvTab` 以“左侧 sticky 说明，右侧配置卡”拆开复杂设置，避免长表单失去上下文。
3. 模型路径通过“配置集 + 基础路径 + 类别映射”分层，变量编辑器通过同步滚动的行号槽降低排错成本。
4. 加速页按预设、显存、性能、精度和辅助配置分组，而非把所有开关堆在一个面板。

不采用或需要升级的部分：

1. 原项目页面协调器与 `TabContainer` 已同时承担保存、预设导入导出、导航拦截和多类配置分发；ComfyNeko 将以小型受控组件和纯草案域隔离这些职责。
2. 原项目很多设置会立即写入环境配置或触发真实环境改变；ComfyNeko 高风险字段一律先保存本地草案，只有未来的 `ChangePlan` 才能修改外部环境。
3. 原项目全局为所有元素添加颜色/背景/边框过渡，并使用玻璃模糊和多处渐变；ComfyNeko 只给可交互组件与面板切换添加短动效，避免性能、可读性和减少动效偏好受损。
4. 原项目的部分路径字段使用固定宽度；ComfyNeko 路径控件采用可收缩网格、`min-width: 0`、断词和原生打开操作，优先保证长 Windows 路径可见可用。

## 非目标与安全边界

- 不读取或写入 `extra_model_paths.yaml`、启动 `.bat/.ps1`、ComfyUI 配置、Python 环境或系统环境变量。
- 不伪造 GPU、CUDA、PyTorch、插件、API 或模型数量；没有探测结果时明确显示“等待环境检查”。
- 不将“保存配置”误导为立即修改运行环境。第一阶段的保存只保存 ComfyNeko 本地环境档案和页面草案。
- 后续真正应用高风险字段时，必须进入 `ChangePlan`：差异预览、明确确认、备份、审计日志与撤销路径。

## 页面骨架

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ENVIRONMENT / 当前档案 / ACTIVE 或 待检查    [保存本地草案]          │
│                    通用设置 | 加速与架构 | 模型路径 | 环境变量        │
├─────────────────────────────────────────────────────────────────────┤
│ 区块说明、图标、辅助操作                   配置面板                  │
│ 例如：环境身份与核心路径                   名称、ComfyUI、Python     │
│                                                                     │
│ 区块说明、图标、风险提示                   配置面板                  │
│ 例如：网络服务与目录映射                   API、输入、输出、临时目录 │
└─────────────────────────────────────────────────────────────────────┘
```

- 顶部命令区在页面内容滚动时保持 sticky；状态文字来自已知探测结果，绝不只靠绿色颜色表达状态。
- 页签使用 `role="tablist"`、左右方向键切换、Enter/Space 激活；活动面板保持可见焦点。
- 宽度大于 900px 时，每个 section 是 `minmax(210px, .85fr)` 说明列 + `minmax(0, 1.45fr)` 配置列。
- 900px 以下折成单列；420px 以下页签允许横向安全滚动或换行，但页面本身不得横向溢出。

## 四个页签与字段分级

### 1. 通用设置

| 分区 | 字段 | 第一阶段行为 |
| --- | --- | --- |
| 环境身份 | 环境名称、默认环境标记 | 本地档案可编辑；默认环境只作为草案标记 |
| 核心路径 | ComfyUI 根目录、Python、Pip 解释器显示 | 根目录/Python 沿用现有选择、打开与自动发现；Pip 仅由 Python 路径推导显示 |
| 运行时探针 | Python、PyTorch、CUDA、SageAttention、FlashAttention、Triton、xFormers | 仅显示真实 probe 结果或等待检查状态 |
| 本地服务 | 监听地址、端口、SSL、CORS | 端口继续使用现有档案字段；其余为本地草案，不修改启动参数 |
| 目录映射 | Input、Output、Temp、User、Workflows | Input/Output/Workflows 保留真实根目录；Temp/User 为本地草案，写入前需要 ChangePlan |

### 2. 加速与架构

以“预设 + 细项覆盖”的形式展示。可选预设为“稳定兼容”“平衡运行”“性能优先”“自定义”；预设只填充本地草案，不操作 GPU 或启动脚本。

- 运行时事实：GPU、显存、CUDA、API 状态，只读且有来源标记。
- 草案字段：显存策略、注意力实现、精度、预览方式、日志级别、网络监听建议。
- 风险说明固定展示：字段会影响启动稳定性，现阶段只保存草案；未来执行必须生成 ChangePlan。

### 3. 模型路径

保留“配置集”概念，默认只有当前环境一个配置集。第一阶段支持选择当前配置集并编辑本地映射草案。

- 基础路径：沿用真实 `models` 根目录列表、选择与打开操作。
- 子类别映射草案：Checkpoints、LoRAs、VAE、Text Encoders、ControlNet、Upscalers、UNet、CLIP Vision。
- 每条草案映射显示“继承基础路径”或“自定义草案”来源；空映射不创建文件夹。
- 不扫描、不移动、不重写 `extra_model_paths.yaml`。

### 4. 环境变量

- 左列展示格式、允许的示例和风险；示例不可直接执行。
- 右列是带视觉行号的纯文本草案编辑器，支持 `KEY=VALUE` 和 `#` 注释。
- 编辑器首次可用，但保存只写 ComfyNeko 本地草案；错误行显示行号和原因，空行/注释忽略。
- 禁止以任何形式把值写入进程、系统变量或启动脚本。

## 组件边界

- `EnvironmentSettingsPage.tsx`：页面状态、标题栏、保存本地草案入口、通知状态。
- `EnvironmentSettingsTabs.tsx`：可访问页签和键盘切换。
- `GeneralEnvironmentSettings.tsx`：核心路径、探针、本地服务和目录映射。
- `AccelerationSettings.tsx`：预设、草案覆盖与只读运行时事实。
- `ModelPathSettings.tsx`：配置集、根目录和模型子类别映射。
- `EnvironmentVariablesSettings.tsx`：行号、解析错误、草案编辑器。
- `environmentSettingsDraft.ts`：前端类型、默认值、预设填充和变量解析，必须是无副作用的纯函数。

`EnvironmentWizard.tsx` 可作为迁移适配层短期保留，最终只负责已保存环境选择和兼容旧调用，不能继续承载所有新界面逻辑。

## 视觉与动效

- 延续 ComfyNeko 蓝紫强调色和深浅主题 Token；不引入装饰性渐变、玻璃拟态或无意义的大卡片嵌套。
- 每个 section 的说明列使用图标、标题、最多两句说明和一个可选辅助操作；配置列使用单一面板，字段行以细分隔线组织。
- 页签切换：180ms 不透明度与 4px 纵向位移；配置区不因页签内容高度不同突然跳动。
- 输入、按钮、页签：Hover 160ms，Active 100ms，Focus ring 清晰；加载按钮锁定重复提交且保留可读文字。
- 保存草案成功：仅出现短暂确认反馈，不制造庆祝性动画。
- `prefers-reduced-motion: reduce` 下移除 transform、淡入和任何循环动画。

## 可访问性与国际化

- 新增可见文案同时进入 `zh-CN` 和 `en-US`；长英文使用缩略而非挤压布局。
- 所有纯图标操作保留 Tooltip、`aria-label` 和键盘可达性。
- 每个 editable control 有唯一 label、帮助文本与 `aria-describedby`；变量解析错误通过 `aria-live` 宣布。
- 所有状态提供图标和文字；暗色/亮色对比度保持可读。

## 验收

1. 通用、加速、模型路径、环境变量四页签在 1366px 形成统一的说明列 + 配置列结构。
2. 核心路径的自动发现、手动编辑、原生选择、打开目录和保存环境仍可用。
3. 预设、模型细分类与变量编辑只影响内存/本地草案，不产生对 ComfyUI 的写入。
4. 变量解析能准确报告无等号、空键和重复键的行号。
5. 亮/暗/跟随系统、中文/英文、240/320/420/1366px、键盘与减少动效均通过检查，浏览器控制台 0 error。
6. UI 评分至少 85/100；动效以反馈为目的，不抢占专业工具的阅读效率。
